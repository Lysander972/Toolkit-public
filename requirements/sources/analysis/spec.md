# analysis Specification

## Purpose

Issue #71 交付零件全局变量表、零件方法级局部变量表和方法调用图，供后续 Lint 消费。

分析仅基于 BES 三层转换的第一层结果及实体抽象层的数据结构。内联脚本和代码仓库脚本采用同一零件方法语义：共享源码可以共享 AST，方法身份和变量归属属于零件上的绑定。

## Requirements

### Requirement: 纯函数与实体关联输入

分析 MUST 消费既有 `LogicalEntitySnapshot`、按工程相对路径关联的第一层 `LocalAst` 和显式平台语义。载体、零件、脚本组、脚本绑定、源码路径和 GUID MUST 来自实体层合同；符号表保留载体与零件实体引用，全局变量表以零件实体身份为键，不复制身份、类型、逻辑名或导入关系形成平行实体模型。实体层拥有身份、层级和文件归属校验，分析不重复实现这些结构校验。

分析 MUST 仅有纯函数接口，同输入生成同结果，不修改或冻结输入，不持有跨调用状态、缓存或订阅，不读取文件、配置、时间或生成 TS AST/文本。一次计算中的局部集合仅用于生成本次结果，不建立有状态分析实例。

Host 的实体装配、监听、状态发布和生命周期继续遵循 `file-entities` 与 `toolkit-runtime`；#71 不改变其服务装配或依赖方向。第三层切片打印和视图缓存归 #47，具体 Lint 规则及可达性、死代码和递归分析归后续消费业务。

#### Scenario: 实体快照与第一层结果

- **WHEN** 输入实体层逻辑快照和已解析的第一层 AST
- **THEN** 分析按实体清单建立文件关联，不进行 IO；重复运行结果相同，输入保持原样

### Requirement: 零件全局变量表与方法局部变量表

每个零件 MUST 从 `LogicalDevice.variables` 生成全局变量表；`None` 表示没有变量文件，生成空表。每个声明脚本绑定 MUST 独立保留零件方法身份，成功解析的绑定生成局部变量表，代码仓库源码不得以文件级身份代替方法级身份。

局部绑定 MUST 复用第一层 `LocalAstSchema.bindings`，包含形参及正文返回值绑定的首次出现候选；重复赋值不覆盖首次绑定，返回引用不额外声明变量。局部变量表 MUST 排除该零件全局变量表的同名项，两表按名称互斥。相同共享源码在不同零件上的局部表取决于各自全局变量表；内联与仓库绑定使用同一规则。

项目职责仅为实体变量投影、按零件方法绑定关联 AST，以及排除全局名称；不自研变量扫描器或复制第一层变量收集。变量类型兼容性属于后续语义检查，不由本表猜测。

方法 MUST 保留绑定身份、零件身份、组类型、事件名、绑定名及清单私有性；成功解析的源码身份、源码 GUID、相对路径、AST、有效私有性和局部变量表统一包装在 `analysis: Option<MethodAnalysis>` 中，源码 GUID 继续使用 `Option`。来源或 AST 缺失时分析为 `None`，声明身份仍留在同一方法表，不建立平行绑定表或空 AST。共享源码的第一层变量收集在单次计算内复用；全局名称、内联来源、调用图的零件身份、载体归属及方法归属使用单次计算索引，索引不跨调用保留。行为验证覆盖共享仓库与内联源码身份、不同零件的局部表、重复计算及输入不变。

绑定身份 MUST 使用实体脚本组身份及清单位置，保留重复名称的独立候选。内联按组内来源路径关联；仓库按 GUID 唯一关联来源。不同对象的 GUID 重叠仅属于数据错误，MUST 通过实体快照的全局唯一性检查明确报错并终止计算，不作为正常业务歧义处理，不选取任一对象继续生成分析结果。多个绑定引用同一 GUID 表示共享同一源码对象。分析入口调用一次实体层检查，仓库关联复用实体层索引查询，不另建 GUID 冲突诊断体系。来源或 AST 缺失 MUST 输出诊断。成功解析时有效私有性为事件绑定、清单私有或源码头私有；未解析绑定只采用明确已知的组类型及清单私有性，不猜测源码头。自定义方法按绑定别名查找，不用源码头名称替代。

#### Scenario: 零件方法作用域与来源诊断

- **WHEN** 两个零件引用同一仓库源码，其中一个零件有同名全局变量
- **THEN** AST 共享，方法身份独立；各自局部表排除本零件全局名称，内联同内容绑定产生同样结果

- **WHEN** 清单引用缺失或第一层 AST 未提供
- **THEN** 输出来源诊断，保留声明方法身份，其分析为 `None`

### Requirement: 显式平台与回调语义

平台方法 MUST 按调用种类、属主类型和方法名完整匹配。回调仅由显式参数位置及调用者/可见载体规则识别，不猜测方法名。String 常量是完整绑定名称，不拆点号；变量目标保留可见候选及未知目标诊断。没有平台登记或回调规则的非脚本调用保留未解析记录。

#### Scenario: 同名方法签名隔离

- **WHEN** 调用与回调规则名称相同但种类或属主类型不同
- **THEN** 不应用该规则，未知平台调用保留诊断

- **WHEN** 延迟调用的回调位于第一个参数、动画事件的回调位于第三个参数，且调用方提供对应完整签名规则
- **THEN** 依据各自参数位置生成回调边；删除规则后重新计算得到未知平台诊断，先前结果保持不变

### Requirement: 调用作用域与目标

普通零件在所属载体解析数字 ID 或逻辑名，类型必须一致，`this` 指自身。显式导入机械时按唯一 GUID 解析机械，`this` 的执行身份为其核心零件，方法闭包采用本次调用者的绑定，保持源码与绑定身份分离。核心类型由平台输入提供，不按零件类型数字猜导入关系。地图与机械保持独立，导入不成为嵌套包含。

GUID 引用缺失、核心或别名缺失与歧义 MUST 保持未解析并保留全部候选，不跳到其他载体同名目标。作用域与可见性是调用图的领域职责；实体合同及第一层 AST 不提供调用目标解析。导入机械的零件绑定属于其核心执行闭包；其他零件只能访问生成器类型的内置 Act，不能访问该绑定。可见回调候选遵循同一闭包边界。

#### Scenario: 导入与跨载体身份

- **WHEN** 数字属主使用带前导零的 ASCII 十进制 ID
- **THEN** 以原生 BigInt 数值比较匹配零件 ID；类型约束保持一致，第一层原调用字段和来源拼写保持原样

- **WHEN** 地图零件导入机械并调用 this、数字 ID 或逻辑名
- **THEN** 目标限制在对应机械；当前核心闭包使用调用者绑定，原核心物理绑定不混入当前方法候选

### Requirement: 方法调用图

调用图 MUST 只遍历成功解析方法的第一层 AST 结构化调用字段，跳过 skip 脚本与禁用语句的调用，继续遍历禁用控制壳内的启用子语句。每条边与未解析记录 MUST 保留绑定来源、工程相对路径、正文物理行、sourceRef 和原调用字段。

act MUST 先解析目标及全部同名自定义声明绑定。同名声明超过一个时保留全部候选并报告歧义；唯一绑定跨零件明确私有时报告私有访问，否则分析缺失时报告 `missing-source`，成功解析且允许访问时生成静态边。缺失目标保留诊断；事件不作为普通方法暴露。仅当目标没有同名自定义声明绑定时使用已登记的平台方法及其回调规则，来源或 AST 缺失不得触发平台回退；此优先级与既有 `CallMapping.signature` 一致，分析不依赖第二层转换实现。

项目实现仅负责 AST 调用到领域边与诊断的映射，不实现通用图遍历、可达性、强连通分量或 Lint 规则。

#### Scenario: 静态调用与未解析调用

- **WHEN** 输入正常调用、重复方法、私有方法和已登记的平台同名方法
- **THEN** 自定义绑定优先，合法调用生成静态边，其余保留准确位置与候选诊断

- **WHEN** 自定义绑定缺失来源或 AST，且存在同名平台方法及回调规则
- **THEN** 调用保留该绑定的 `missing-source`，不应用平台方法或回调规则；两个同名声明中只有一个成功解析时仍报告歧义

### Requirement: 回调候选边

唯一成功解析的常量回调目标生成 dynamic 边；常量多候选生成指向已解析候选的 potential-static 边并保留全部候选的歧义；变量生成指向已解析可见候选的 dynamic 边及全部候选的 dynamic-target 诊断。候选只包含自定义声明方法，明确跨零件私有绑定和被当前闭包替换的机械核心物理绑定不可见。分析缺失但未明确禁止访问的声明保留为未确认候选，额外输出包含这些绑定身份的 `missing-source`，不生成指向缺失分析者的边。错误参数及缺失回调目标 MUST 保留诊断。

#### Scenario: 常量与未知回调目标

- **WHEN** 回调参数为唯一常量、歧义常量、变量、错误类型或缺失名称
- **THEN** 返回对应候选边及诊断，未知目标不冒充确定静态调用

- **WHEN** 常量或变量回调候选包含缺失来源或 AST 的声明绑定
- **THEN** 保留完整候选身份及 `missing-source`，只向已解析候选生成边；常量是否歧义按完整候选数判断
